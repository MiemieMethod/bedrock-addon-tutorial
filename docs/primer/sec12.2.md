# 自定义角色部件

在更衣室中，我们可以分别选择发型、上衣、帽子和其他装饰，这很容易使我们产生一个设想：能否像添加物品一样，通过普通附加包向更衣室加入一件自己的帽子？在开始制作之前，我们需要先区分经典皮肤、角色创建器部件和世界内装备外观。

## 三种相似的外观

**角色创建器**（**Character Creator**）允许玩家组合多种外观部件，相关角色系统也常被称为**Persona**。这些部件涉及客户端支持的角色结构、部件资源及相应的分发与授权流程。普通皮肤包中的一张PNG图片，与其中的一件可组合部件不是同一种资源。

另外，玩家在世界中穿戴的盔甲、拿在手中的物品，也能够呈现模型和纹理。这类外观可以涉及**附着物**（**Attachable**），其作用范围与装备物品相联系，而不是在账户的更衣室中新增一个永久部件。

| 我们希望完成的目标 | 优先选择的方式 | 作用范围 |
| --- | --- | --- |
| 为经典玩家外形绘制一套服装 | 经典皮肤或皮肤包 | 选中的经典皮肤 |
| 在自己的地图中显示一件帽子或工具 | 物品、装备与附着物 | 加载该作品的世界 |
| 在更衣室中分发可组合的角色部件 | 官方角色部件创作与发布途径 | 对应平台的角色系统 |

这张表有助于我们提前决定资源应放在哪里。把一个附着物的标识符写进皮肤列表，不会自动把它转换成角色创建器商品。

## 普通附加包的可行实践

对于一个“让实验世界中的研究员戴上特色头盔”的需求，我们可以先采用资源包中的装备外观。为了降低第一步的复杂度，先基于原版钻石头盔进行观察，再在独立作品中扩展为自定义物品。

我们读取的原版`attachables/diamond_helmet.json`中，主要关系如下：

```json
{
  "format_version": "1.8.0",
  "minecraft:attachable": {
    "description": {
      "identifier": "minecraft:diamond_helmet",
      "materials": {
        "default": "armor",
        "enchanted": "armor_enchanted"
      },
      "textures": {
        "default": "textures/models/armor/diamond_1",
        "enchanted": "textures/misc/enchanted_actor_glint"
      },
      "geometry": {
        "default": "geometry.humanoid.armor.helmet"
      },
      "scripts": {
        "parent_setup": "variable.helmet_layer_visible = 0.0;"
      },
      "render_controllers": ["controller.render.armor"]
    }
  }
}
```

这个文件说明了装备标识符、材质、纹理、模型与渲染控制器之间的关系。我们可以在测试资源包中复制该定义，将普通纹理引用改为自己的路径，例如`textures/tutorial/researcher_helmet`，然后放入采用原版盔甲UV布局绘制的图片。

这一次修改只替换钻石头盔附着物所使用的普通纹理引用，不要同时修改模型和渲染控制器。给测试玩家一顶钻石头盔，穿戴后切换第三人称观察，检查正面、背面、头部转动以及附魔时的表现。若外观没有变化，依次检查资源包优先级、纹理路径和内容日志。

我们采用不同的纹理路径，是为了避免仅仅覆盖共享的`diamond_1`图片而连带改变其他盔甲的表现。不过，覆盖`minecraft:diamond_helmet`本身仍会与修改同一原版装备的包发生冲突，所以它适合作为独立实验，而不是通用附加包的最终设计。

## 从实验走向自定义装备

确认模型、纹理和装备显示关系之后，再创建自己命名空间下的物品，并根据目标版本的可穿戴组件设置头部装备槽。随后使对应附着物引用自己的模型、纹理和渲染控制器。物品负责“能够怎样装备与使用”，附着物负责“装备时怎样显示”，这两个职责应分别验证。

在制作模型时，我们还需要考虑玩家皮肤的宽手臂与细手臂差异、蹲下和游泳等姿态，以及第一人称与第三人称的显示。一个静止姿态下没有穿模的模型，未必在动画中也正确。最有效的办法是建立固定的动作检查场景，而不是仅凭Blockbench中的预览作结论。

世界内的装备也不会自动同步成玩家账户拥有的角色部件。玩家离开该世界后，其他世界是否加载相同资源，决定了对应外观是否仍然存在。发布说明应明确这一点，避免把地图装备描述成可在所有服务器使用的更衣室服装。

## 如果目标确实是Persona部件

对于更衣室中可组合、可分发的角色部件，应根据官方当前提供的Marketplace创作者流程确认资格、制作规范和提交要求。官方角色创建器FAQ将自定义配件创作指向Marketplace合作伙伴途径；这与普通附加包的本地导入流程不同。

一些客户端或导出工具可以显示内部角色字段，但“能够看到某个结构”并不等于“普通内容包可以注册并发布该结构”。我们不能根据内部字段名猜测一个`persona`目录、伪造商品标识符，或把未公开格式包装成可以稳定工作的教程。若将来官方开放新的公开创作入口，应以该入口的文档和样本为依据更新本节。
