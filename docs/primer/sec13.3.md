# 将世界打包为世界模板

当地形、实体和玩法都已准备好后，我们希望玩家能够从相同的起点开始自己的游戏。如果直接把作者正在游玩的世界发给玩家，便可能连同已完成的任务、移动过的物品和测试痕迹一起发出。**世界模板**（**World Template**）则用于提供一个可重复创建新世界的起点。在本节中，我们将一起把测试完成的世界整理为模板。

## 世界文件与模板文件

`.mcworld`通常用于导入一个世界副本，导入后出现在世界列表中；`.mctemplate`用于导入模板，玩家再从模板创建自己的世界。两者都可以包含世界数据和需要的包，但导入后的使用方式不同。

模板也不是“自动清除进度”的工具。我们必须先把源世界整理为正确的初始状态，再导出。若源世界中的箱子已经被拿空，或任务记分板已经处于完成状态，创建模板不会自动猜出作者原本希望的数值。

## 整理发布用的源世界

复制一个专门用于发布的世界，检查出生位置、时间、天气、游戏模式和任务状态。清除测试实体与临时命令设施，恢复初始物品，并确认玩家不会在未完成区域出生。必要的资源包与行为包应在这个世界中实际激活，而不仅仅存在于作者的开发目录。

随后保存退出，通过客户端提供的世界导出功能得到`.mcworld`。把它复制一份改为`.zip`，解压到工作目录。正常的世界内容应包括`level.dat`和`db`目录；带附加包的世界还可能包括`behavior_packs`、`resource_packs`及其世界包列表文件。

我们应保留整个`db`目录。模板采用固定场景时，这些正是建筑与地形的数据；删除它会失去已经制作的世界。随机种子模板属于另一种设计，不能与当前固定地图的打包步骤混用。

## 添加模板清单

在世界内容根目录创建`manifest.json`：

```json
{
  "format_version": 2,
  "header": {
    "name": "pack.name",
    "description": "pack.description",
    "uuid": "f43e5cb6-06a3-47fa-9539-599b64b8bd93",
    "version": [1, 0, 0]
  },
  "modules": [
    {
      "type": "world_template",
      "uuid": "8881db57-16ca-4427-8153-66e8d9bece20",
      "version": [1, 0, 0]
    }
  ]
}
```

`world_template`说明这个包提供世界模板。模板自己的UUID与其中资源包、行为包的UUID不是同一回事。复制本例制作新的独立作品时，应为模板生成新的两个UUID；更新同一模板时，则保留身份并增加版本。

若作品需要使用基础游戏版本控制等额外能力，应单独阅读对应字段的文档，不要为了消除警告而随意添加未知字段。本例先保留官方模板教程中最基本的清单结构。

## 名称、描述与世界包列表

创建`texts/languages.json`：

```json
["en_US", "zh_CN"]
```

在`texts/zh_CN.lang`中填写：

```text
pack.name=附加包实验世界
pack.description=从一个准备好的场景开始学习附加包。
```

同时在`texts/en_US.lang`中提供对应英文名称与说明。可以保留导出世界已有的`world_icon.jpeg`，也可以制作反映实际初始场景的图片。图标只负责展示，不能代替世界数据或清单。

如果世界使用资源包，检查`world_resource_packs.json`中的`pack_id`与对应资源包清单的`header.uuid`一致；行为包列表也同样检查。版本数组应与实际包含的包一致。这里引用的是包头UUID，而不是模块UUID。

例如，假设世界确实包含本章的PBR实验包，其资源包列表可以引用该包的包头UUID：

```json
[
  {
    "pack_id": "6996c799-2e6e-440e-820e-ecbf1208cc9c",
    "version": [1, 0, 0]
  }
]
```

没有包含或没有打算启用该包时，就不应机械地添加这条记录。包列表描述的是当前世界的真实依赖。

## 压缩正确的一层

选择世界根目录中的全部内容进行ZIP压缩，再将扩展名改为`.mctemplate`。打开压缩文件时，第一层就应看到`manifest.json`、`level.dat`和`db`，而不是先看到一个作者电脑上的工作目录名。

附加包目录也应保持简短。官方模板指南提醒，世界内的资源包和行为包文件夹名应控制在10个字符以内，以规避部分主机平台的路径问题。我们可以把它们命名为`lab_rp`和`lab_bp`，并在清单中使用完整的展示名称。

`examples/presentation/world_template_metadata/`只提供本节新增的清单和本地化文本，必须与真实导出的世界内容结合；它本身不是一个已经包含地形的模板。

## 用两个新世界验证模板

在支持导入模板的客户端中导入文件后，到新建世界流程中的已导入模板区域寻找它。它没有直接出现在普通世界列表中，并不代表导入失败。

从模板创建世界A，移动一个容易识别的方块并保存。随后再次从同一模板创建世界B，确认B仍保留原始方块位置。这个小实验可以验证我们分发的是可重复创建的初始内容，而不是反复打开同一个已修改存档。

继续检查两次创建时的资源加载、出生位置、任务初值和日志。最好在不包含开发目录资源的另一套测试环境中导入一次，以发现“作者电脑有依赖，所以看不出遗漏”的问题。模板更新也不会自动改写玩家此前创建的世界，因此存档迁移需要另行设计。
