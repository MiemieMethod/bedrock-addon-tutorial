# 认识资源包

在第一章中，我们只使用行为包便实现了一个新的配方。这是因为原料和结果都已经存在于原版游戏中，游戏知道它们应该显示成什么样子。如果希望让它们换一种外观，或者为新的内容提供自己的模型与声音，就需要用到**资源包**（**Resource Pack**）了。

## 资源与定义

我们可以先从一张方块纹理出发。纹理图片本身保存了像素的颜色，而决定“使用哪张纹理”的数据，则可能存放在另一个定义文件中。对于实体而言，还需要告诉游戏使用哪个模型、哪种材质、哪些动画。这些内容互相配合，才能得到屏幕上的最终结果。

因此，资源包并不只是一个装图片的文件夹。它既可以包含图片、声音等资源，也可以包含组织和引用这些资源的JSON定义。我们常说的**纹理包**（**Texture Pack**）通常是以替换纹理为主要用途的资源包；不能反过来认为每个资源包都只有纹理。

| 资源包中的位置 | 主要用途 |
| --- | --- |
| `textures` | 方块、物品、实体、界面等使用的纹理，以及部分纹理图集定义 |
| `models` | 几何模型等定义 |
| `entity` | 客户端实体定义，注意这里使用单数 |
| `animations`、`animation_controllers` | 动画与动画控制器 |
| `render_controllers` | 渲染控制器 |
| `sounds` | 音频文件与`sound_definitions.json` |
| `texts` | 不同语言的文本 |
| `particles` | 粒子效果定义 |

这张表是用来帮助我们查找内容的，不是要求每个包都创建所有目录。一个只修改泥土纹理的资源包，暂时不需要模型、动画或粒子目录。

## 为教程创建资源包

在工作目录中新建与`Tutorial_BP`并列的`Tutorial_RP`文件夹，在其根目录新建`manifest.json`，写入：

```json
{
    "format_version": 2,
    "header": {
        "name": "教程资源包",
        "description": "用于学习纹理、声音和文本的资源包。",
        "uuid": "0b03ed47-759e-42bf-bc72-d5a36ba90c83",
        "version": [1, 0, 0],
        "min_engine_version": [1, 21, 0]
    },
    "modules": [
        {
            "type": "resources",
            "uuid": "d6f01c89-4d16-48e6-8d20-d7fa41f84942",
            "version": [1, 0, 0]
        }
    ]
}
```

与行为包的清单相比，最关键的变化是模块的`type`变成了`resources`。UUID也换成了独立的一组，不能直接沿用行为包的两个UUID。按照第一章的方法，将它放入`development_resource_packs`，再在测试世界的资源包设置中激活。

此时游戏应当能够显示“教程资源包”，但是世界的外观不会变化。我们尚未添加任何资源，所以这个结果恰好符合当前文件的内容。不要把“看起来没有变化”直接理解为清单无效。

## 包堆叠与资源覆盖

玩家可以同时激活多个资源包，这些包会构成一个**包堆叠**（**Pack Stack**）。当多个包提供同一路径的可覆盖资源时，具有更高优先级的资源会被选用。世界包列表中靠上的包通常具有更高优先级，因此测试时应当注意资源包的排列顺序。

我们可以用下一章的泥土纹理实验验证这一点：准备两个不同UUID的资源包，分别在`textures/blocks/dirt.png`放入不同颜色的图片，然后交换两者的先后顺序。重新加载后，泥土外观应当随优先级变化。这里被比较的是相对于包根目录的资源路径，而不是两个包文件夹是否同名。

不过，不同类型的JSON定义还可能具有专门的合并或覆盖规则，不能从“一张图片被覆盖”推出“所有JSON文件一定都是整份替换”。遇到复杂定义时，应当查看该类文件的文档，并用小范围实验验证。

## 资源包应该承担什么工作？

假设我们将来要制作一个蓝色的小动物。资源包负责告诉客户端它的模型是什么、使用哪张蓝色纹理，以及移动时如何播放动画；行为包则负责它的生命值、移动行为和交互规则。即使资源包把模型画得很大，也不能仅凭模型外观推断服务端碰撞箱同样变大。

也正因为两端的职责不同，复制客户端实体JSON到行为包的`entities`中通常无法产生预期效果。文件的目录、根对象以及字段格式，都应当符合对应一端的要求。

在本章，我们先把资源包准备好。接下来的纹理、声音和翻译练习都可以在这个包上继续添加，每完成一项便重新加载并检查一次。若只有其中一种资源无效，应先检查这一类资源的路径和引用，而不是把整个资源包推倒重来。
