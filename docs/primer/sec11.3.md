# 自定义字体

在制作界面时，我们除了调整文字的位置和颜色，还可能希望文字本身具有不同的外观。比如，为标题制作像素风格的字形，或在任务提示中加入一个小图标。这样的需求经常被统称为“自定义字体”，但在基岩版中，我们首先需要分清字形替换与新增字体系统之间的区别。

## 字符与字形

**字符**（**Character**）是文本中的抽象单位，**字形**（**Glyph**）则是它被绘制出来时的视觉形状。同一个字符可以使用不同字形显示，而两幅相似的字形也不一定代表同一个字符。

例如，聊天消息中的字母`A`仍然是同一个字符。我们改变它的位图形状之后，搜索、复制或脚本中的字符串比较并不会因此把它变成另一个字母。这种方法改变的是显示资源，而不是文本语义。

基岩版的资源包可以涉及`font`目录下的字体图像资源；这不等于Java版的字体提供器配置。我们不能把Java版的`assets/命名空间/font/default.json`放入基岩版，然后期待其中的字体提供器自动运行，也不能仅凭把一个TTF文件放入资源包就获得任意字体切换能力。

## 先检查目标版本的原始资源

字体修改依赖客户端实际使用的资源，因此我们先准备与目标客户端版本相符、具有合法使用来源的原始字体资源。公开的`bedrock-samples`并不保证包含客户端使用的全部字体文件；某个目录未出现在样本仓库中，也不能说明客户端根本不存在对应资源。

在一些使用传统位图字形布局的资源中，我们会遇到`font/default8.png`或`font/glyph_XX.png`一类文件。这里应当保留目标版本实际存在的路径、尺寸、透明通道和布局，不要仅凭文件名推测任意图片都能被识别。

尤其需要区分两类布局：Unicode分页字形表可以按照码位分页；默认紧凑字形表可能使用自己的映射顺序。不能把ASCII码直接套到任意`default8.png`的格子位置上。

## 完成一次最小的字形替换

我们先选择一个在目标原始字形图中能够明确识别的拉丁字母，例如`A`，只修改这一个字形。

1. 创建独立的测试资源包，准备正常的资源包清单。
2. 将目标字体图复制到资源包中的同一路径，保留原始文件作为对照。
3. 在图像编辑器中使用像素网格放大观察，只在选中字形原有的单元格内修改笔画。
4. 保留单元格周围的透明区域，不改变整幅图片尺寸，不移动其他字形，也不对整张图片做平滑缩放。
5. 在测试世界中加载该包，使用包含`A`与相邻字符的句子检查结果。

我们可以用下面的命令准备一段简单的对照文本：

```mcfunction
/tellraw @s {"rawtext":[{"text":"ABC XYZ 0123456789\n附加包字体测试：AaBbCc"}]}
```

如果只有预期字母发生变化，说明我们找到了对应资源与字形位置。若一整段字符错位，通常应先检查图片尺寸和网格布局；若笔画边缘出现模糊色块，应检查是否在缩放或导出时引入插值。若完全没有变化，则需要检查资源优先级、客户端是否使用该字体资源，以及当前界面是否采用了另一条文本渲染路径。

## 理解Unicode分页位置

对于确实采用`glyph_XX.png`、每页256个字符并以16列排列的字形表，我们可以用码位计算位置。设字符码位为 $u$，则页编号为 $\lfloor u/256\rfloor$，页内编号为 $u\bmod256$；行号为 $\lfloor (u\bmod256)/16\rfloor$，列号为 $u\bmod16$，行列都从0开始。

例如，U+E100位于E1页的第0行第0列。这个计算只说明该传统布局下的位置，不承诺当前客户端一定从我们提供的E1页读取它。使用私用区之前，还需要确认目标版本和同时加载的资源包没有占用同一码位。

**私用区**（**Private Use Area**）中的码位没有统一的公共字形含义。如果我们把某一码位画成任务图标，其他玩家在没有相应资源包时可能看到方框、空白或另一幅图案。因此，重要提示仍应保留普通文字，不应只依赖一个私用区图标传达操作含义。

## 范围、兼容性与替代方式

字体图覆盖往往影响多个界面，而不是只影响我们自己的标题。游戏中的聊天、记分板或旧式界面可能共同使用某一资源；新式界面却未必走相同的路径。因此，完成测试后还需要检查长句换行、中文与英文混排、GUI缩放，以及不同输入设备上的提示文字。

官方协作式附加包指南明确指出，字体字形文件的覆盖难以与其他包可靠组合。如果作品承诺支持玩家任意叠加其他附加包，应优先保留原字体；装饰性标题可以考虑使用图像控件，普通交互文字则通过布局、字号和颜色改善可读性。

输入按键的图标也不宜简单绘制成固定的键盘按键图片。当前接口在部分文本入口中支持输入字形替换，使提示可以随设备变化。使用前应检查该入口的支持情况；这与新增任意私有字体仍是不同能力。
