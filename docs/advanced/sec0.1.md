# 认识JS的语法

在入门教程中，我们通过JSON文件描述了许多游戏内容。现在，我们希望在某件事情发生时读取当时的数据，进行判断，再执行不同的操作。比如，玩家完成一次挑战之后，我们先计算分数，再判断是否达到了奖励条件。这便需要使用一种能够描述执行过程的程序语言。

**JavaScript**，简称**JS**，正是本教程接下来使用的语言。它的核心语法由**ECMAScript**规范定义，而Minecraft通过脚本引擎执行这些语法，并另外提供访问世界、实体和物品的接口。我们先学习语言本身，再学习这些接口，这样在遇到错误时，便能够分清问题究竟出在语法、数据，还是游戏提供的功能上。

## 从一段可以运行的程序开始

首先，我们观察下面这段代码。暂时不用记住每个符号的名称，只需尝试顺着它的执行顺序读一遍。

```js
"use strict";

const playerName = "小明";
let score = 3;
score = score + 2;
console.log(playerName);
console.log(score);
```

在提供`console.log`的JavaScript环境中运行，我们会依次看到两行输出：

```text
小明
5
```

我们可以看到，这段程序先记录一个名字和一个分数，然后把分数增加2，最后将名字和新的分数打印出来。`"小明"`、`3`和`2`都是直接写在代码中的值，这种表示值的写法称为**字面量**（**Literal**）；`playerName`和`score`则是我们给数据起的名字。`console.log(...)`负责把括号中的结果交给环境显示，这里的点号和圆括号将在后面的对象与函数两节中详细解释。

为了让读者能够独立验证，本章的普通JavaScript示例均可分别保存为一个UTF-8编码的`.mjs`文件，在已安装Node.js的环境中使用`node 文件名.mjs`执行。每个代码块都是一次独立实验，不要直接把全章所有代码拼成同一个文件，否则重复声明的名字可能造成错误。浏览器的开发者工具控制台也适合许多小实验，但其顶层环境与模块文件不同，涉及`this`时应以本教程标明的环境为准。

这里使用Node.js只是为了观察语言行为。它不意味着Minecraft能够使用Node.js的文件系统、`process`或第三方包，也不意味着游戏提供网页中的`window`、`document`和计时器。**语言语法与宿主接口是两件事情**。以后在行为包中执行代码时，我们还需要正确配置脚本模块、入口与依赖；相关操作将在[初识脚本API](./sec1.1.md)中完成。

## 表达式与语句

程序中能够被求值得到结果的结构称为**表达式**（**Expression**）。比如`3 + 2`得到`5`，而`score + 2`则先读取`score`当前的值，再完成加法。描述一个执行步骤的结构称为**语句**（**Statement**），例如将表达式结果赋给已有变量的`score = score + 2;`便是一条表达式语句。

这里的等号不应按照数学等式理解。数学中的`x = x + 2`通常无法成立，而程序中的等号要求我们先计算右侧，再更新左侧。它表达的是一次操作，不是在断言左右两侧永远相等。因此，阅读程序时除了关心数值，还要关心先后顺序。

多数简单语句可以使用英文分号`;`结束。JavaScript存在**自动分号插入**（**Automatic Semicolon Insertion**）规则，但这并不等于每一次换行都会插入分号，也不等于分号可以随意删除。本教程统一显式书写分号，将`return`与其返回的表达式写在同一行，避免依赖容易误读的换行行为。由花括号构成的条件或循环语句块则按对应语法书写，不在每个右花括号后机械地添加分号。

## 名称、注释与排版

**标识符**（**Identifier**）是变量、函数等结构所使用的名字。初学时，我们可以采用英文字母开头、后续由字母和数字构成的名字，也可以使用下划线或美元符号；名字不能以数字开头，不能使用`const`、`return`等保留字。JavaScript区分大小写，因此`score`与`Score`是两个不同的标识符。为了减少辨认成本，本教程使用`playerName`这样的驼峰式命名。

`//`开始单行注释，`/*`与`*/`包围多行注释。与严格JSON不同，注释本身便属于JavaScript允许的语法，不过多行注释不能直接嵌套。注释适合解释“为什么这样处理”，例如“只计算已经完成的挑战”；至于“把1加到分数上”这种代码本身已经说明的事情，则无需每行再重复一次。

开头的`"use strict";`启用**严格模式**（**Strict Mode**），使某些容易被忽略的错误明确暴露出来。例如，未经声明便给一个名字赋值，在严格模式中会报错。`.mjs`对应的模块本身已经采用严格模式，示例保留这行是为了让复制到普通脚本中的实验也具有一致的基本约束。

空格与缩进大多用于帮助人类阅读。我们在运算符两侧保留空格，用四个空格缩进语句块，并让对应的花括号容易辨认。熟悉了JSON之后，这些排版方式应该并不陌生；不过，字符串内部的空格属于数据，不能为了对齐而随意删改。

## 亲手修改与检查

请先把示例中的初始分数改为8，再把增加量改为4，运行前预测输出。结果应为`小明`与`12`。然后交换增加分数和打印分数两条语句的位置，观察为何打印结果变成8。最后将某一处`score`改成`Score`，根据报错定位拼写不同的位置。

这三个实验分别检查数值计算、执行顺序和名称一致性。调试时先阅读错误所指向的文件和行号，再回到前后语句检查，不必一看到报错就将整段代码重新抄写。下一节，我们将进一步解释这些名字如何被声明，以及数据如何发生变化。
