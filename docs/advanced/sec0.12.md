# 了解字符串模板

游戏中的提示往往同时包含固定文字和运行时的数据。例如，我们希望显示“小明完成了3轮挑战，获得9分”。如果每遇到一个数值便使用加号连接，字符串稍长时就很容易漏掉空格、标点或引号。**模板字面量**（**Template Literal**）为这种文本提供了更直接的写法，也常被称为字符串模板。

## 观察插值的位置

```js
"use strict";

const name = "小明";
const rounds = 3;
const message = `${name}完成了${rounds}轮挑战，获得${rounds * 3}分。`;

console.log(message);
console.log("${name}完成了挑战。");
```

输出分别为`小明完成了3轮挑战，获得9分。`与`${name}完成了挑战。`。两者区别在于外侧定界符：模板字面量使用英文**反引号**，即`` ` ``，而普通双引号字符串不会解释`${...}`。不要将反引号写成中文引号，也不要误以为任何字符串中的美元符号都会触发计算。

`${...}`中的内容是一个表达式。执行到模板时，JavaScript计算表达式，并将其结果转成适合连接的字符串。这里既可以读取变量，也可以完成算术或调用函数，不过复杂逻辑最好先在模板外计算完成，再把结果填入。这样文本仍然像文本，而不是藏着一整段难以调试的程序。

## 模板不会自动持续更新

```js
"use strict";

let score = 2;
const oldMessage = `分数：${score}`;
score = 8;
const newMessage = `分数：${score}`;

console.log(oldMessage);
console.log(newMessage);
```

输出为`分数：2`和`分数：8`。一个模板字面量在执行时得到的只是普通字符串，它不会建立界面与变量之间的自动联系。想显示新分数，需要再次执行生成文本的代码。我们可以把这一过程封装成`formatScore(score)`函数，在分数变化或界面刷新时调用。

这点在Minecraft中尤其容易误会：先保存一段带`${score}`的文本，并不等于为计分板或动作栏注册一个会自行变化的表达式。模板插值发生在JavaScript执行阶段，而文本何时被发送、界面何时刷新，则由后续调用的游戏接口决定。

## 多行文本与转义

模板字面量可以直接跨行，其中的换行和空格通常都会成为最终字符串的一部分。为了看清哪些字符确实被保存，我们可以通过`JSON.stringify`显示换行的转义形式。

```js
"use strict";

const summary = `挑战结果
玩家：小明
分数：9`;
const literal = `这里显示\${score}和一个反引号\``;

console.log(JSON.stringify(summary));
console.log(literal);
```

第一行输出为`"挑战结果\n玩家：小明\n分数：9"`，第二行输出为``这里显示${score}和一个反引号` ``。反斜杠可以使`${`不被当作插值起点，也可以使反引号不结束当前模板。双引号与单引号在模板内通常不需要额外转义，但反斜杠本身仍然有转义意义。

如果我们在源代码中为了排版缩进了多行模板，这些缩进也可能出现在游戏消息里。可以先用数组保存各行，再使用`join("\n")`连接，或者在生成文本时明确处理缩进。不要认为编辑器中的“看起来整齐”就自动等于最终显示结果整齐。

## 字符串化不是格式化规则

```js
"use strict";

const point = { x: 1.25, y: 64, z: -2.5 };
const names = ["小明", "小红"];

console.log(`对象：${point}`);
console.log(`位置：${point.x.toFixed(1)}, ${point.y}, ${point.z}`);
console.log(`玩家：${names.join("、")}`);
```

输出为`对象：[object Object]`、`位置：1.3, 64, -2.5`与`玩家：小明、小红`。普通对象的默认字符串形式不会自动列出属性，所以面向玩家的消息应该明确选择想显示的字段；调试时若需要结构化内容，可以使用`JSON.stringify`，并留意循环引用或不可序列化的数据。

`toFixed(1)`返回一个保留一位小数的字符串，它适合显示，但不代表原始数值被改成了精确的一位小数。浮点舍入也仍然受数值表示影响。如果后续还需要计算，应保留原来的数值，将显示格式仅用于输出阶段。

## 标签模板与使用边界

模板还可以跟在函数名后面，形成**标签模板**（**Tagged Template**）。标签函数会分别收到固定文本片段和插值值，可以实现特定格式的处理，返回值甚至不一定是字符串。普通模板直接拼接的规则与标签函数的自定义行为不同，阅读第三方代码时需要先确认前面的函数是什么。

无论采用哪种模板，都不能假设插值会自动执行JSON转义、命令参数验证、HTML转义或本地化。若需要生成JSON，应先构造普通对象再用`JSON.stringify`；若调用游戏命令，应遵循该命令的参数规则，优先使用具有明确参数类型的脚本接口。把任意文本放进`${...}`只是生成文本，并不能证明这段文本已经适合另一个解析器。

请写一个`describeReward(name, amount)`函数，返回“某玩家获得某数量个绿宝石”。分别传入0和3，确认0不会被替换成默认奖励。再让名字包含双引号，观察普通消息仍能正确生成，但如果手工把同样的名字塞进JSON引号中，会出现什么额外要求。这样便能区分语言插值与目标格式各自负责的工作。
